tom_i2c_check  -  WHAT A GOOD RUN LOOKS LIKE                       version 1.7
=============================================================================
Compare what you see with this. Times are approximate. The date and time
will be yours. Lines starting with "BIST" and "POST" are in the Serial
Monitor (optional); the screens are on the LCD and the LED.


1. SERIAL MONITOR, FIRST SECONDS
   ==== tom_i2c_check version 1.7 | built Oct  8 2026 11:31:56 | board UNO R4 Minima ====
   Type help for the commands.
   Last reset: power-on (cold start)   (RSTSR0=00 RSTSR1=0000 RSTSR2=00)
   POST 1/4 LCD ok   answers at 0x23
   POST 2/4 RTC info was 2020-01-01 00:00:03; SET from compile time to 2026-10-08 11:31:56
   POST 3/4 LED ok   0x24 + digits 0x34-0x37 answer
   POST 4/4 O2  ok   answers at 0x74 (the O2 test reads it; nothing is changed)
   POST OK. The LCD / RTC / LED test starts by itself in 3 s.

   - RTC line "info ... SET from compile time" appears the FIRST time (the RTC
     was out of date). On later runs it reads:   POST 2/4 RTC ok   2026-10-08 11:35:10
   - "Last reset:" says what restarted the program: "power-on (cold start)"
     after power was applied, "reset button/other" after the RESET button.
     The three register values are for the record.
   - If a device is missing the line says FAIL (or "info" for the O2 sensor)
     and POST ends with "POST: PROBLEMS FOUND".


2. THE SCREENS

   After 2.5 s, during the POST (LCD):
       CHECK v1.3 TBS0 TOB0
       LCD+ RTC+ LED+ O2+
       2026-10-08 11:31:56
       test starts soon
     (TBS0 TOB0 = both switches off. LED: the time, e.g. 1131, with the
      middle dot blinking.)

   LCD step (about 17 s). The LED shows -001. The LCD shows, one after
   another (each for 3 s):
       ####################          ABCDEFGHIJKLMNOPQRST ...
   then the backlight blinks (3 s), then the text vanishes and returns
   (3 s). Every row must be readable and complete.

   RTC step (3 s): the LED shows -002.

   LED step (about 18 s): 8888 with ONE dot (after the second digit),
   0000 1111 2222 3333 4444 5555 6666 7777 8888 9999 (0.4 s each), one
   dark second, then it returns. LCD row 4 says what it is doing:
       LED: all segments / LED: count 0 to 9 / LED: blink off/on

   O2 step (1 s): the LED shows -004.

   TBS step (up to 20 s): the LED shows -005. The LCD shows
       row 3:  now:off seen:off
       row 4:  FLIP TBS ON then off
     and when you flip the switch ON then OFF:  now:ON seen:ON off  and it
     passes at once.

   TOB step (up to 20 s): the LED shows -006. Row 4: PRESS TOB, RELEASE.
     Same.

   RESET step (up to 20 s): the LED shows -007. Row 3: (the program
     restarts)   Row 4: PRESS RESET NOW. Press the RESET button: the
     screens go through the start-up again (LED ----, the LCD blank for a
     moment, then the status lines) and row 4 shows for 20 s:
         RESET test: PASS

   The result (row 4 of the LCD), the two screens alternating every 3 s:
       TEST LCD? RTCP LED?
       TEST O2P TBSP TOB?
       TEST RST?
     A good run with nobody typing p or f and the switches operated:
       LCD?  (looked right to you, not typed)    RTCP   LED?
       O2P   TBSP   TOBP   RSTP
     If you type p after the LCD and LED steps those show P instead of ?.
     A "?" is not a failure. An "F" is.


3. SERIAL MONITOR, THE TEST (what each step prints)
   TEST: 7 steps (LCD, RTC, LED, O2, TBS, TOB, RESET). Look at the displays; ...
   BIST 1/7 LCD
      LCD: backlight blinking
      LCD: display blinking (the text should vanish and return)
      Did you see 4 readable rows, then the backlight blink, then the display blink?  (p = yes, f = no; no answer is fine)
   BIST 1/7 LCD OK? (no I2C error; judge by eye)           <- or "PASS" if you typed p
   BIST 2/7 RTC
      RTC reads 2026-10-08 11:32:16; waiting 3 s to see it advance
      RTC advanced 3 s while the clock of this board advanced 3 s; chip 23.25 C
   BIST 2/7 RTC PASS  23.25 C
   BIST 3/7 LED
      LED: 8888 with one decimal point (all segments)
      LED: counting 0000 .. 9999
      LED: display off for 1 s, then on
      Did you see 8888 with one dot, the count 0-9 on all digits, and one blink?  (p = yes, f = no; no answer is fine)
   BIST 3/7 LED OK? (no I2C error; judge by eye)           <- or "PASS"
   BIST 4/7 O2
      O2 raw reply: FF 86 08 3A 05 02 00 00 xx             <- the 9 bytes the sensor sent
      O2 sensor reads 20.90 %  (gas type 0x05; 0x05 = O2)
   BIST 4/7 O2  PASS  20.90 %
   BIST 5/7 TBS
      TBS is off now. Flip TBS ON and then OFF within 20 s.
   TBS ON
   TBS off
   BIST 5/7 TBS PASS  both states seen
   BIST 6/7 TOB
      TOB is released now. Press TOB and then release it within 20 s.
   TOB pressed
   TOB released
   BIST 6/7 TOB PASS  both states seen
   BIST 7/7 RST
      PRESS THE RESET BUTTON NOW (within 20 s). The program restarts; at the next start it reports the result.
   ... (you press RESET: the program restarts, the log starts again with the banner) ...
   ==== tom_i2c_check version 1.7 | built ... | board UNO R4 Minima ====
   Last reset: reset button/other   (RSTSR0=00 RSTSR1=0000 RSTSR2=01)
   RESET TEST: PASS The RESET button restarted the program (reset cause: reset button/other).
   POST ...                                (the normal start-up, then the test starts again)
   TEST complete: 5 pass, 0 fail, 2 not confirmed (?), 0 skipped. It repeats in 45 s ...

   Notes:
   - A p or f typed after the 8 seconds ran out answers the last unanswered
     question:   Recorded: LCD PASS (your late answer to the question that timed out).
     and the result for that step changes from ? to P (or F).
   - The O2 reading depends on what the sensor is breathing: about 20.9 %
     in room air; a few percent or less in the nitrogen output when the
     generator has been running; it needs about 5 minutes after power-on to
     settle. "reads exactly 0.00 %" is reported as a FAIL (a fault).
   - If the O2 sensor is not fitted: "O2 sensor: no answer at 0x74 (not fitted?
     it is not part of the I2C parts test)", then "BIST 4/7 O2  ?  not found",
     and the result shows O2?  (not a failure).
   - If power is removed instead of pressing RESET, the report says:
        RESET TEST: ? The RESET test was running, but this start was a POWER-ON ...
     and the step shows RST?  (the Arduino lost power: not a button press).
   - If nobody presses RESET the step ends after 20 s: "BIST 7/7 RST ?  not pressed".
   - If you do nothing at the TBS / TOB steps they end after 20 s with
     "TBS ... not exercised" and show ? in the result.


4. THE I2C SCAN  (type scan in the Serial Monitor)
     0x23  LCD backpack
     0x24  LED module (TM1650)      (also 0x25, 0x26, 0x27)
     0x34  LED module (TM1650)      (also 0x35, 0x36, 0x37)
     0x57  RTC module EEPROM
     0x68  DS3231 RTC
     0x74  O2 sensor
     I2C scan 0x08-0x77: 12 device(s)
   The LED module answering ALL of 0x24-0x27 and 0x34-0x37 is normal.
   The LCD must be at 0x23. An LCD at 0x27 would clash with the LED module.


5. IF A STEP SAYS FAIL
   Copy the Serial Monitor text (Ctrl+A, Ctrl+C) and send it back together
   with what you saw on the LCD and the LED. The lines above and below the
   FAIL line say which device and what went wrong.
